# 本地开发代理配置

> 仅适用于**本地开发机（大陆网络）**。生产 VPS 在海外可直连 IBKR，**不需要**代理。
>
> 反方向链路（生产 VPS 借本机 Clash 访问新浪/腾讯国内行情）见 [VPS回国代理配置.md](./VPS回国代理配置.md)。

## 一、解决的问题

本地启动仪表板后，`/api/portfolio` 返回：

```json
{"error":"Unable to load IBKR Flex data","message":"fetch failed"}
```

原因是 IBKR Flex 服务域名 `ndcdyn.interactivebrokers.com` 在大陆被墙，本地直连超时。
`fetch failed` 是**网络层错误**（对端不可达），不是凭证错误——凭证错误时 IBKR 会返回自己的业务错误（如 `IBKR SendRequest failed`）。

排查连通性：

```bash
curl -I --max-time 20 https://ndcdyn.interactivebrokers.com   # 超时 = 被墙
curl -I --max-time 20 https://www.alphavantage.co             # 正常
curl -I --max-time 20 https://openapi.longbridge.cn           # 正常
```

## 二、整体链路

```
本地 Node 服务
   │  /api/portfolio
   ▼
Clash Verge（127.0.0.1:7897）
   │  Reality 隧道（伪装成访问目标站点的 HTTPS）
   ▼
东京 VPS（Xray VLESS Reality，监听 443）
   │
   ▼
ndcdyn.interactivebrokers.com（IBKR Flex）
```

端口分工：**nginx 占 80**（反代仪表板容器）、**Xray 占 443**（代理），互不冲突。

## 三、配置步骤

### 1. 服务端（海外 VPS）

1. 安装 Xray，采用 **VLESS + Reality** 方案（无需域名/证书，伪装成真实大站 HTTPS，抗 DPI）
2. 监听 443，`flow=xtls-rprx-vision`，配置 `dest` / `serverNames` / `shortIds`
3. **云厂商控制台防火墙放行 TCP 443**（最容易漏，漏了一定连不上）

### 2. 客户端（本地 Windows）

1. 安装 [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev/releases)
2. 导入 VLESS Reality 节点配置（server / port / uuid / public-key / short-id / SNI）
3. 打开 **系统代理 / System Proxy**（让浏览器走代理）
4. 节点延迟测试出绿色毫秒数即隧道正常

节点配置示例（参数替换成自己的）：

```yaml
mixed-port: 7897
mode: rule

proxies:
  - name: tokyo-reality
    type: vless
    server: <VPS IP>
    port: 443
    uuid: <UUID>
    network: tcp
    tls: true
    udp: true
    flow: xtls-rprx-vision
    servername: <Reality SNI>
    client-fingerprint: chrome
    reality-opts:
      public-key: <Reality 公钥>
      short-id: <shortId>

proxy-groups:
  - name: PROXY
    type: select
    proxies: [tokyo-reality, DIRECT]

rules:
  - GEOIP,CN,DIRECT
  - MATCH,PROXY
```

### 3. Node 服务走代理

已在工程内配置好，直接：

```bash
npm start
```

## 四、关键技术点（为什么这样配置）

Node 的 fetch 代理由两个启动期机制控制：

- `--use-env-proxy`：让 fetch 识别 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量
- `HTTP_PROXY` 等代理地址：在 Node **bootstrap 阶段一次性读取并缓存**

**坑**：这两者都不能靠 dotenv（`server.js` 执行时）注入，那时已经太晚，实测仍 `fetch failed`。
**解**：用 Node 启动参数在 bootstrap 早期注入。

工程最终配置：

`package.json`（会提交，对生产安全）：

```json
"start": "node --env-file-if-exists=.env --use-env-proxy server.js"
```

- `--env-file-if-exists`：bootstrap 早期加载 `.env`；文件不存在时静默跳过（生产容器无 `.env` 不报错）
- `--use-env-proxy`：生产无代理变量时等同直连，行为不变

`.env`（被 gitignore，仅本机）：

```bash
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
# 仅 IBKR 走代理；长桥/AV/CNN 本来就能直连，排除掉避免绕路和 Clash 未开时连带失败
NO_PROXY=127.0.0.1,localhost,longbridge.cn,alphavantage.co,production.dataviz.cnn.io
```

## 五、踩坑记录

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | `YAML syntax error line 2` | 复制时把 ` ```yaml ` 围栏也粘进去 | 用干净的 yaml 文件 |
| 2 | 节点正常但 Google 打不开 | Windows 系统代理没开 | Clash Verge 打开系统代理 |
| 3 | 系统代理开了 Node 仍失败 | Node fetch 默认不走系统代理 | `--use-env-proxy` + 代理变量 |
| 4 | 代理变量写进 `.env` 仍失败 | dotenv 加载晚于 bootstrap 缓存 | 改用启动参数早期注入 |
| 5 | `EADDRINUSE 3000` | 旧 Node 进程没退干净 | 结束占用端口的进程 |
| 6 | 长桥行情也走代理、Clash 关了行情也挂 | 所有出站请求都走代理 | `NO_PROXY` 白名单 |

## 六、使用注意

- 看持仓数据时**先开 Clash Verge**；没开只有 `/api/portfolio` 失败，行情等接口不受影响
- 生产 VPS 直连 IBKR，**无需任何代理**，本配置不影响生产部署
